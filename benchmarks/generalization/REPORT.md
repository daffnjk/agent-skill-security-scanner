## 结论

完成了源码修改、三套公开数据上的五种候选/消融对比，以及第四套独立来源的冻结外部验证。最小候选在前三套数据上保持召回率、减少误报，但在外部 600 个完整 Skill 包上新增 2 个漏报。严格模式 F2 从 85.43% 降至 84.96%，未通过预先规定的“召回不退化”门禁。没有达到“各项指标尽可能全面改善”的交付目标，不将此候选作为生产升级推荐。没有修改 main、创建 release 或合并 PR。

基线源码为 `9a69854cbcbd1dd2d092f2f3ec0409ed50868932`，本次实测基线引擎 `v41-hardening.1`，不是历史 v41 报告。最终实验源码提交 `b201c6a44bda8ac6d5747cba6ead96ea07dce62b`，引擎标识 `v41-context-safe.1`。其中“safe”只是内部版本字符串，不表示通过安全/泛化验收。实际测量使用冻结前构建的同源二进制，commit 字段为 `context-safe-frozen`；其全部非测试 Go 源文件 SHA-256 由 FINAL_FREEZE.json 绑定，发布流程再次逐项校验。

先固定源码、数据版本与校验和，再登记开发/留出划分。仅从 Agent Skill Malware 开发部分分析误报，优先修正行为证据边界，不调低阈值、不用样本 ID、固定攻击域名或数据集名称特判。初版加入词边界、近邻关联、条件载荷要求和 Markdown 代码块行为分析；冻结其哈希后才打开留出结果。

## 4. 外部失败如何影响决策

600 个包中，两个原本输出 malicious 的恶意包变成 benign；良性包中有一个 suspicious 变 malicious、一个 malicious 变 suspicious、一个 malicious 变 benign。因此严格模式净减少 1 个误报，但新增 2 个漏报；筛查模式同样新增 2 个漏报。不能把“误报变少”宣传为无条件提升。

配对按组 bootstrap 使用 2,000 次重采样、固定种子 20260906。外部严格召回差的 95% 区间为 [-1.6893, 0] 个百分点，F2 差为 [-1.3128, +0.1587] 个百分点；区间包含零，不声称统计显著提升或显著退化。预先规定的工程验收门禁要求观测召回不退化，仍然必须失败。

前三套数据的 bootstrap 使用原始 holdout 标记子集；因这些子集后来参与消融选择，区间只是描述性结果，不提供无偏泛化证明。外部 bootstrap 使用全部 600 个独立组代表。

## 5. 防过拟合与数据质量

原始三来源共 2,495 条记录，精确内容、可得仓库/技能名、URL 与长十六进制归一化后的词三元组余弦相似度 >= 0.90 构建连通分组。得到 1,718 组；开发仅使用 232 条 Agent Skill Malware。与开发簇重叠的 43 条其他来源记录单列为 overlap_regression，不混入初始留出。原始划分和全部样本 ID/标签/组哈希保留在清单中。

外部 SkillTrustBench 原始有标签记录 5,520 条。联合前三来源重新查重后，排除 97 条重叠记录，剩余 1,946 个无重叠连通分组。先按不依赖标签的 ID 哈希选择每组代表，再按组哈希选 300 个 malicious、300 个 normal，保留完整包字节和路径。338 个 suspicious 组代表没有参加二分类。这个平衡子集不是完整 5,520 条评测，也不代表真实部署恶意率。

分组不能保证已知/未知攻击家族完全隔离：有些来源没有攻击家族或仓库元数据；相似度阈值也不能捕获所有变体。所有来源均为公开数据，历史版本可能已接触，因此“外部”仅指本次候选选择未使用，不能称为项目历史上绝对未见数据。没有完成攻击家族留一验证、时间前推验证、动态沙箱或全部其他包级基准。

SkillsBench 有 8 条伴随脚本文件名冲突，均保留为不同路径并标记，未静默丢弃；完整 JSON/CSV 包含去掉这 8 条的敏感性分析。外部一条非 UTF-8 文档仅在查重时使用替换解码，扫描仍使用原始字节。

工程验证包括 gofmt、go vet、Go 单元测试、竞态测试、38 个 Python 测试（包含 12 个新增评测/材料化测试，提供真实 CLI 时无跳过）、既有 4+26 场景 selftest 和失败关闭测试。词边界 fuzz 一轮 5 秒完成 173,088 次执行，无失败。新 Go 测试覆盖词边界、良恶成对行为、域名替换、MCP 引用/执行区别和端到端扫描。这些测试只证明所测软件契约，不证明泛化通过。
