# 持续提升检出能力：评估、提案、独立验收

本功能构建可审查的循环，不承诺每轮都涨分，也不通过扩大误报或反复试探测试集换取“更高检出率”。没有真实改善时不提 PR；任何扫描不完整、数据不一致或指标退步都阻断提案。不会自动合并、发布或修改基准标签。

## 两条工作流

| 工作流 | Asia/Taipei 时间 | 作用 |
| --- | --- | --- |
| `Detection regression loop` | 每日 04:23；也支持 PR / 手动触发 | 当前代码与固定基线在相同数据上配对扫描，输出可追溯指标与非退步检查 |
| `Propose detection improvement` | 每周一 03:17；也支持手动触发 | 可选的开发集分析 → 一个候选补丁 → 完整测试 → 独立回归 → 草稿 PR |

上述时间由 UTC cron 换算，GitHub 调度可能延迟；计划任务只有合并到默认分支后才生效。自动改进默认关闭；本次基础设施变更本身不代表检测率已经提高。

## 启用

先审查并合并本功能的 PR，查看 `Detection regression loop` 的实际运行结果。每日评估不需要模型 API 密钥。若首次评估发现标签冲突、解析失败或扫描不完整，先解决对应问题，不能删除难例、降低门槛或把失败算成 benign 来获得绿灯。

启用模型辅助改进需要仓库维护者在 GitHub 设置中完成：

1. 在 Actions secrets 配置 `OPENAI_API_KEY`。使用专用项目、最小额度并设置费用告警；不要把密钥写入仓库或 Issue。
2. 在 Actions variables 设置 `DETECTION_AUTOFIX` 为字符串 `true`。
3. 在 Actions 的 workflow permissions 中允许 GitHub Actions 创建 pull request。组织策略也必须允许所用 Actions 和相应权限。

工作流固定第三方 Action 的提交 SHA，只在 `main` 上运行模型，不向 fork PR 提供模型密钥。模型服务用量和 Actions 资源会产生相应成本；本功能没有替维护者配置密钥或启用付费调用。

在 Actions 页面手动运行任一工作流可验证配置。设置 `DETECTION_AUTOFIX=false` 停止自动改进；日常只读回归不受影响。初始预算仅允许记录中的前 8 次非 skipped 自动改进工作流执行，包括手动运行和失败；一个待审提案存在时暂停生成新提案。预算依赖 GitHub 运行历史，不是不可篡改的审计账本。不要通过删除历史或重复运行绕过预算；耗尽后应审查数据暴露、补充新数据并通过协议变更 PR 决定后续实验。

## 初始数据与实际含义

数据来自另一个项目 `daffnjk/agent-skill-security-datasets` 的固定、校验过的 MIT Release，配置在 [`sources.json`](../benchmarks/continuous/sources.json)。

| 来源 | 用途 | 原始数量 | 正 / 负 |
| --- | --- | ---: | ---: |
| Agent Skill Malware | 开发集，优化器可查看 | 347 | 124 / 223 |
| ATR Skill Benchmark | 不提供给本轮优化器的跨来源回归集 | 498 | 32 / 466 |

共 845 条原始记录。下载文件、上游版本和 SHA-256 固定；缓存也必须重新核验摘要。每次先校验原始标签计数，再进行统一去重与污染检查，不会静默忽略解析失败、空文本、未知标签或重复身份。

**这两个来源均已用于历史 v41 评测，不是从未见过的最终测试集。** 因此报告永远明确 `generalization_proven=false` 和 `release_approved=false`。新协议去重后分母可能小于 845；不得直接把新分数与历史未去重全量分数相减来宣称收益。每日任务在同一份材料化数据上重新运行基线与候选，保证本轮可比。

不同任务的标签语义不能混用。当前适配器仅接受所声明来源的 `malicious` / `benign`；`suspicious`、`vulnerable`、运行时攻击或通用提示词注入不自动充当包级恶意真值。接入新来源要另加适配器、标签审核和测试，不能把元数据误当完整 Skill。当前两源仅扫描文本，不代表多文件包与运行时行为覆盖。

## 防止过拟合与数据泄漏

先在全部本轮来源上分组，再隔离开发集与回归集。分组规则包括 NFKC / 大小写 / 空白归一化后的完全重复、5 词片段 Jaccard ≥ 0.85 的近重复，以及相同 frontmatter `name`。同源完全重复只计一次；与开发样本同组的回归样本被隔离并记录数量。完全相同文本的标签冲突直接阻断，交给人工研判。近重复变体仍可在同一来源中计分，但保留组身份用于统计诊断。

分组是保守近似，不是完整作者、仓库或攻击家族溯源。它可能漏掉语义改写，也可能把通用名称合并。不得宣称所有跨来源重叠都已消除。报告保存原始数、保留数、剔除原因及有效组数；每个必需来源至少保留 10 个正例、10 个负例，否则不能接受候选。

优化器每次只获得开发集，只提出一个有行为解释的假设。它不能修改评估脚本、工作流、标签、数据切分、基线或依赖；补丁必须含生产代码与测试，最多 5 个 `cmd/detector/*.go` 文件、300 个变更行、60 KB。提示词要求恶意/良性成对反例及结构不同的变体，禁止样本 ID、数据集名称、Skill 名字或已知 IP/域名名单式刷分。路径和补丁预算由可信脚本执行，语义泛化仍需维护者审查。

候选代码测试、外部回归验收和写入 PR 分属全新 runner。外部回归只验收一次选定补丁，不把逐样本结果反馈给该轮优化器。计时重复不是额外调参机会。历史结果、公开数据和模型预训练暴露仍无法被完全排除，所以使用次数受限且只创建草稿 PR，不自动部署。

## 指标与验收门槛

按来源分别报告严格口径（仅 malicious 阳性）和筛查口径（malicious + suspicious 阳性），不把不同来源混成一个漂亮总分：

- TP / FP / TN / FN、Precision、Recall、F1、F2、FPR、Specificity、Accuracy、Balanced Accuracy、MCC。
- 召回率与误报率的 Wilson 95% 区间；这些边际区间以独立样本为假设，相关样本会使区间偏乐观。
- 回归集按近重复组汇总的探索性配对符号检验，以及可用 `source_family` 分层指标。小样本或多次尝试不应被包装成显著泛化结论。
- 两个镜像预热后，交替顺序运行 3 轮，记录整批扫描耗时及中位数。它包含容器启动开销，不是单 Skill p95，也不等同于内存实测曲线。

通过非退步门槛需要：每个来源的严格和筛查 FP、FN 均不增加；每个已有 family 的严格 FP、FN 均不增加；候选整批耗时中位数不超过基线的 1.20 倍加 150 ms；所有输入均有唯一、完整、合法且多次一致的结果。没有漏报增加，也不能用新误报换取总体召回提升。

在上述条件外，至少一个非开发来源的严格 FP 或 FN 必须真正减少，才会设置 `proposal_ready=true`。相同结果可以通过回归，但不能创建“提升”PR。当前采用保守 Pareto 门槛；若业务确需指标权衡，应先独立批准代价函数与容忍度，不能在看过候选结果后临时放宽。

稳定 CLI 只有离散 verdict，因此不伪造 PR-AUC、ROC-AUC 或校准结果。持续分数与每样本延迟需另行定义输出契约后再纳入。

## 安全与产物

归档不整体解压；只读取唯一声明的 JSONL 普通成员，拒绝穿越路径、链接、设备文件和超出预算的归档。样本只写为不可执行的 `SKILL.md` 数据，目录身份经过摘要化，不把标签或来源名称暴露给扫描器。样本、URL、证据文本都不是指令，禁止安装、导入、执行或访问其中的链接。

正式评估的静态二进制运行在 `FROM scratch` 容器：断网、只读根文件系统、非 root、无 capabilities、无提权、有 CPU / 内存 / 进程 / 超时限制。只挂载只读输入和临时输出，不提供模型密钥或仓库写令牌。exit 2/3、超时、缺行、多行、重复身份、不完整 metadata 和非法 verdict 全部失败关闭，不从分母中消失。

完整测试可执行候选 Go 测试，因此放在单独的无模型密钥、无仓库写权限 job；正式验收 worker 不执行候选测试。生成 PR 的 job 只有在验收通过后才获得写权限，并且不构建或执行候选代码。若 main 已移动则丢弃本轮提案；不强推、不删除分支、不自动合并。关闭的候选分支需由维护者按正常审查流程清理后才能再次使用。

每日产物 `detection-report-<run_id>` 包含 `report.json`、`summary.md` 或 `failure.json`，保留 30 天。候选补丁保留 7 天。只发布聚合指标、配置摘要、版本与剔除计数，不发布原始样本、载荷、证据或逐条外部回归预测。超过保留期的审计材料应由维护者另行归档。自动 PR 使用 GITHUB_TOKEN；GitHub 对此类事件的后续工作流触发有限制，不要把没有再次触发 PR CI 误判为“已经检查”。提案工作流已先执行独立测试与评估，合并仍须正常人工审查。

## 最终泛化验收：仍需新数据

发布前，由不参与优化的维护者准备一个在规则冻结后采集、按作者/仓库/攻击家族去重且与开发来源不同的时间后移留出集。数据和标签放在优化器无读取权限的位置；本实现没有凭空创建或声称拥有这样的密封数据源。

候选、协议、阈值、主指标与最小样本量先冻结，之后独立评估一次。报告每来源与关键攻击类别结果、置信区间、扫描完整性及完整成本；失败不返回逐样本细节给同轮优化器。若必须用失败样例修复，把该批数据正式移为开发/回归并更换最终留出集，不能继续称它为未见测试集。

补充作者/仓库/家族标注、扩大困难负样本和独立恶意家族覆盖，是下一阶段数据建设任务；不靠随机把已经用过的 845 条重新切分来获得“未见”资格。

## 本地复现与维护

需要 Python 3.10+、Go（与现有 CI 保持一致）及 Docker；下载阶段需要访问固定 GitHub Release，正式扫描断网。不要在安装 Skills 的目录中放置样本。

```bash
PYTHONPATH=scripts python3 -m unittest discover -v -s scripts -p 'test_detection_loop.py'
git worktree add --detach ../skillscan-baseline 9a69854cbcbd1dd2d092f2f3ec0409ed50868932
bash scripts/build_detection_image.sh ../skillscan-baseline skillscan-baseline:loop
bash scripts/build_detection_image.sh . skillscan-candidate:loop
python3 scripts/detection_loop.py evaluate \
  --baseline-image skillscan-baseline:loop --candidate-image skillscan-candidate:loop \
  --baseline-ref 9a69854cbcbd1dd2d092f2f3ec0409ed50868932 --candidate-ref "$(git rev-parse HEAD)" \
  --cache /tmp/skillscan-evaluation-cache --output /tmp/skillscan-evaluation-report
```

请使用全新的输出目录，避免混淆不同运行的产物。exit 0 表示本轮非退步；1 表示指标门槛不通过；2 表示数据、扫描或完整性失败。配置或标签需变更时单独提 PR，保留旧快照，记录理由；不能连同候选补丁一起修改验收标准。每日比较的固定基线应在正式审查接受后更新，而不是追随任意候选；自动提案则与本轮 main 提交进行配对。
