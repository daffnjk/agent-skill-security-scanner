# 赛事背景、版本边界与最终成绩声明

## 赛事信息

- 赛事：首届火山引擎 AI 安全攻防挑战赛（2026）
- 赛道：赛道 B（蓝队检测挑战）
- 提交形式：Docker 化 Agent Skill 扫描检测引擎
- 输入：`/data/skills/{skill_id}/`
- 输出：`/output/results.jsonl`

赛道使用隐藏的黑、白、灰样本评测检测引擎。公开规则中，检测质量占 55%，性能占 10%，OWASP AST 主分类可解释性占 20%，运行稳健性占 15%。

本仓库明确区分“最终参赛快照”和“赛后持续迭代版本”：

| 分支 | 提交 | 含义 |

`competition/v38-final` 不接受后续功能合并，用于复现当时的代码、输出协议、性能基准和赛事成绩。`main` 是当前用户默认看到和使用的版本，但它不是原始比赛提交，也尚未接受同一赛事环境的重新评测。

因此，下文的 **7.27 / 10** 和 **20+** 排名只属于 `competition/v38-final`，不能作为当前 `main` 的检测质量、可解释性、运行稳健性或性能指标。

## 成绩解读

- **性能 1.00 / 1.00**：最终版本在性能维度获得满分，体现了纯 Go、零第三方运行依赖、离线确定性扫描和有界资源设计的工程优势。
- **检测质量 4.34 / 5.50**：这是总分的主要贡献项，与项目围绕 F₂ 进行高信号召回增强的路线一致。
- **可解释性 1.10 / 2.00**：参赛版本能够输出主 AST 类别和证据，但精确主分类仍有继续提升空间。
- **运行稳健性 0.83 / 1.50**：参赛版本具备异常兜底、资源限制和原子结果写入，但正式评测结果表明该维度仍是后续优化重点。

这些结果解释的是比赛时的 v38 快照。当前 `main` 已经针对扫描完整性、fail-open 路径、规则可达性、确定性、测试覆盖和构建链进行了赛后加固；这些改动属于新的工程迭代，不能被描述为当时已经获得的比赛能力或分数。

## 复现最终参赛版本

```bash
git clone https://github.com/daffnjk/agent-skill-security-scanner.git
cd agent-skill-security-scanner
git switch competition/v38-final

make build
make test
make selftest
```

复现时应记录：

- 分支和完整提交 SHA；
- Go、Docker 和宿主机版本；
- 输入数据集、标签映射和数据快照；
- 扫描输出、失败、跳过和资源限制统计；
- 性能测试的硬件与语料结构。

历史性能数据是特定硬件和合成语料上的结果，不应被直接当作其他环境的吞吐量保证。

## 当前 `main` 的赛后迭代定位

当前主线保留 v38 的离线静态分析方向和四字段比赛输出兼容性，同时继续演进：

- 扫描不完整时不再允许结果保持可信 `benign`；
- 增加 `scan-metadata.jsonl`，区分内容判定与扫描完整性；
- 修正规则大小写、文件类型和文档可达性问题；
- 强化确定性评分、结构化权限解析和回归测试；
- 增加 `go vet`、race、覆盖率和容器构建等工程检查。

这些变化应使用独立的版本号、提交 SHA、测试报告或数据集指标进行描述。除非重新进入同一官方评测环境，否则不得将它们表述为赛事成绩提升。
